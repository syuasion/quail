title: AI functions

Use AI functions to filter and join documents, score answers, assign
labels, and extract text. The examples use BigQuery syntax. See the
[SQL reference](/docs/user-guide/sql) for dialect selection and a first query.

## Functions

Select a function to jump to its arguments, examples, and limits.
Square brackets mark optional arguments.

<div className="function-index">

| Function | Description |
| --- | --- |
| [`PROMPT(template, column, ...)`](#prompt) | Combines instructions with document columns. |
| [`AI.IF(prompt[, options])`](#aiif) | Keeps documents or pairs that satisfy a model question. |
| [`AI.SCORE(prompt[, options])`](#aiscore) | Returns a score from 0 to 1 for a model question. |
| [`AI.CLASSIFY(input, categories[, options])`](#aiclassify) | Assigns one of the supplied labels. |
| [`AI.EXTRACT(input, questions)`](#aiextract) | Copies answers from a document and returns their positions. |
| [`HINT(condition, options)`](#planning-hints) | Sets the estimated pass fraction for a label or answer condition. |

</div>

## PROMPT

`PROMPT` combines a question template with document column references.
The placeholders `{0}`, `{1}`, and so on identify the columns in argument
order.

For a filter, the prompt references one column:

```sql
PROMPT('Does this review discuss the ending of the movie?\n\n{0}', r.body)
```

For a join, the prompt references one column from each table:

```sql
PROMPT('Does the review discuss this aspect?\n\nReview: {0}\nAspect: {1}',
       r.body, a.aspect)
```

Here `{0}` is the review and `{1}` is the aspect.

A prompt argument can also read a struct field or apply a text function
to a column. See [Column expressions](/docs/user-guide/sql/sql-functions#column-expressions).

## AI.IF

`AI.IF` takes a `PROMPT` and evaluates it on each row or each pair
of rows. The model returns TRUE or FALSE.

### Filtering

Use `AI.IF` in a `WHERE` clause to filter rows:

```sql
SELECT r.id
FROM reviews r
WHERE AI.IF(PROMPT('Does this review mention a positive aspect?\n\n{0}', r.body))
  AND AI.IF(PROMPT('Does this review discuss the ending?\n\n{0}', r.body))
```

Use `AND` to combine filters. All AI filters on one table must read the
same document column.

### Joining

Use `AI.IF` to join two tables with a natural language condition:

```sql
SELECT r.id, a.aspect
FROM reviews r, aspects a
WHERE AI.IF(PROMPT('Does the review discuss this aspect?\n\nReview: {0}\nAspect: {1}',
                   r.body, a.aspect))
```

Add column comparisons in `ON` to restrict the pairs the model evaluates.
For example, imagine that each claim has a `wiki_url` identifying its
source passage in an `evidence` table:

```sql
SELECT c.id, e.id
FROM claims c
JOIN evidence e
  ON c.wiki_url = e.id
 AND AI.IF(PROMPT('Does the passage support the claim?\n\nClaim: {0}\nPassage: {1}',
                  c.claim, e.text))
```

The model evaluates only pairs where `c.wiki_url = e.id`.

Beside at least one equality, `ON` can compare two columns with `<`,
`<=`, `>`, `>=`, or `<>`. For example, `ON a.hotel = b.hotel AND a.id <
b.id` over `reviews a JOIN reviews b` asks about each unordered pair of
one hotel's reviews once.

### EXISTS and NOT EXISTS

`EXISTS` keeps a row if the subquery returns at least one match.
`NOT EXISTS` keeps it if the subquery returns no matches.

The following query finds reviews that discuss at least one aspect:

```sql
SELECT r.id
FROM reviews r
WHERE EXISTS (
    SELECT 1 FROM aspects a
    WHERE AI.IF(PROMPT('Does the review discuss this aspect?\n\nReview: {0}\nAspect: {1}',
                       r.body, a.aspect)))
```

Use `NOT EXISTS` to find reviews that discuss none of the listed aspects:

```sql
SELECT r.id
FROM reviews r
WHERE NOT EXISTS (
    SELECT 1 FROM aspects a
    WHERE AI.IF(PROMPT('Does the review discuss this aspect?\n\nReview: {0}\nAspect: {1}',
                       r.body, a.aspect)))
```

The subquery must be `SELECT 1 FROM <table> WHERE AI.IF(...)`.

### Options

Both `AI.IF` and `AI_FILTER` accept an optional second argument with
planning hints:

```sql
AI.IF(PROMPT(...), {'selectivity': 0.3, 'anchor': 'r'})
AI_FILTER(PROMPT(...), {'selectivity': 0.3, 'anchor': 'r'})
```

- **`selectivity`** estimates the fraction of rows or pairs that pass.
  Quail uses it to choose filter and join order. The default is `0.2`,
  meaning 20%. The hint does not change model answers.
- **`anchor`** (joins only) sets the table alias whose document KV is
  reused across pairs. This side is the *anchor*. If omitted, Quail
  selects the anchor using estimated query time. See
  [Joins](/docs/architecture/execution#joins).

## AI.SCORE

Unlike `AI.IF`, which returns only TRUE or FALSE, `AI.SCORE(PROMPT(...))`
returns a score between 0 and 1 as a `FLOAT64`. Higher scores indicate a
stronger model preference for a positive answer to your question.

### Return scores

For example, imagine a `documents` table where each row is a customer
support request. Its `body` column contains the request text. Return the
score for whether each customer requests a refund:

```sql
SELECT d.id,
       AI.SCORE(PROMPT('Does the customer request a refund? {0}', d.body))
           AS refund_score
FROM documents d
```

A score in `SELECT` requires a column alias with `AS`.

### Filter rows

Compare the score with `<`, `<=`, `>`, or `>=`. For the same support
requests, keep rows with a refund score of at least 0.75:

```sql
SELECT d.id
FROM documents d
WHERE AI.SCORE(
    PROMPT('Does the customer request a refund? {0}', d.body),
    {'selectivity': 0.1}
) >= 0.75
```

Choose the threshold using labeled examples from your task. A score of
0.75 does not establish that the model is correct 75% of the time.

The optional `selectivity` hint estimates the fraction of rows that pass
the comparison. It defaults to `0.2` and does not change the scores.
See [Options](#options).

### Join tables

For example, imagine a `queries` table of search queries and a `documents`
table of articles. Match each query with articles whose relevance score
is at least 0.8:

```sql
SELECT q.id, d.id
FROM queries q
JOIN documents d ON AI.SCORE(
    PROMPT('Is {1} relevant to {0}?', q.text, d.body)
) >= 0.8
```

For a prompt that reads two documents, the template must contain `{0}`
once. Refer to that document in words if you need to mention it again.

To return a score for every pair without filtering, use `CROSS JOIN`
and put `AI.SCORE` in `SELECT`.

### Model behavior

All [supported models](/docs/user-guide/models) can run `AI.SCORE`:

- Qwen3 rerankers are trained to score a document's relevance to a query.
  For a prompt with two documents, the first is the query and the second
  is the candidate document.
- [Decision 2.0 Kai](/docs/user-guide/models#decision-20-kai-06b) returns
  its probability of "Yes" when choosing between "Yes" and "No".
- Qwen3 generative models and DiffusionGemma compare their scores for
  TRUE and FALSE answers. Quail converts that comparison to a value
  between 0 and 1.

Quail computes a repeated score once when it appears in `SELECT` and a
condition, or in several comparisons. A query cannot combine `AI.SCORE`
with `AI.IF`.

## AI.CLASSIFY

`AI.CLASSIFY` returns one of your supplied categories as a `STRING`.
For example, imagine a `reviews` table with review text in `body`. Return
a sentiment label for each review:

```sql
SELECT r.id,
       AI.CLASSIFY(r.body, ARRAY['positive', 'negative', 'mixed']) AS sentiment
FROM reviews r;
```

A classification in `SELECT` requires a column alias with `AS`. The call
must be a separate item, rather than part of a larger expression.

### Arguments

`AI.CLASSIFY(input, categories[, options])`

| Argument | Type | Description |
| --- | --- | --- |
| `input` | `STRING` column or `PROMPT` | The document to classify. Use `PROMPT` to add instructions or refer to two documents. |
| `categories` | `ARRAY` or table name | 2 to 255 labels. Labels must not be empty or differ only in case. |
| `options` | Object | Optional parameters listed below. |

Each category can have a description of up to 25 words. For example,
`ARRAY[('refund', 'asks for money back'), ('praise', 'expresses approval')]`.
If labels have the same score, Quail returns the first in the list.

<details>
<summary>Other category formats</summary>

You can supply categories as objects:

```sql
ARRAY[{'label': 'refund', 'description': 'asks for money back'}, {'label': 'praise'}]
```

You can also use a registered table with a `label` column and optional
`description` and integer `ordinal` columns. Quail sorts by `ordinal`
if present, otherwise by label text.

</details>

### Optional parameters

Pass an object as the third argument, such as `{'probabilities': true}`.

| Parameter | Default | Meaning |
| --- | --- | --- |
| `task_description` | Empty | Extra instructions, up to 50 words. |
| `selectivity` | `0.2` | Estimated fraction of rows kept by a condition on the label. Does not change model answers. |
| `probabilities` | `false` | Return each category's probability in `<name>_probabilities`, a `MAP<STRING, DOUBLE>`. |

The probabilities sum to 1. They are available for individual documents;
classifications of joined rows return labels only.

### Query examples

#### Filter by category

Use the classification's `AS` name in `WHERE` to filter by its label.
For example, keep negative or mixed reviews from the `reviews` table:

```sql
SELECT r.id,
       AI.CLASSIFY(PROMPT('What sentiment does this review express? {0}', r.body),
                   ARRAY['positive', 'negative', 'mixed']) AS sentiment
FROM reviews r
WHERE sentiment IN ('negative', 'mixed');
```

- `=` keeps one category. Other comparisons raise `CompileError`.
- A category that is not in the list matches no rows.
- You can also repeat the `AI.CLASSIFY` call in `WHERE`. Quail evaluates
  the classification once and uses its label for both the filter and
  the result.

#### Classify joined rows

Use a `PROMPT` that refers to both documents to classify joined rows.
For example, imagine a `reviews` table of movie reviews and an `aspects`
table of subjects such as acting or plot. Find the aspects each review
discusses and classify its sentiment about each matched aspect:

```sql
SELECT r.id, a.aspect,
       AI.CLASSIFY(
           PROMPT('What is the opinion of the review about the aspect? {0} {1}',
                  r.body, a.aspect),
           ARRAY['positive', 'negative', 'mixed']) AS opinion
FROM reviews r
JOIN aspects a ON AI.IF(
    PROMPT('Does the review discuss this aspect? {0} {1}', r.body, a.aspect));
```

These limits apply:

- The classification and its `AI.IF` join run on one GPU.
- A `WHERE` condition cannot test the label of a joined row.
- A query cannot classify joined rows and also use `AI.SCORE`.

For labels computed before later filters, see
[Classification answers](/docs/user-guide/results#classification-answers).
For the scoring methods, see
[Label scoring](/docs/architecture/execution#label-scoring).

## AI.EXTRACT

`AI.EXTRACT` returns the answer to each of your questions, copied from
a document. For example, imagine a `contracts` table
with contract text in `text`. Return the end date and the signer of
each lease:

```sql
SELECT c.id,
       AI.EXTRACT(c.text,
                  {'end_date': 'When does the lease end?',
                   'signer': 'Who signed the lease?'}) AS lease
FROM contracts c;
```

The result is a struct with one `STRING` field for each question. A
field is null when the document does not answer its question. For a
contract with the text `Lease ends on March 3, 2027. Signed by Ana Ruiz.`,
`lease` is `{"end_date": "March 3, 2027", "signer": "Ana Ruiz"}`.

An extraction in `SELECT` requires a column alias with `AS`. The call
must be a separate item, rather than part of a larger expression.

### Arguments

`AI.EXTRACT(input, questions)`

| Argument | Type | Description |
| --- | --- | --- |
| `input` | `STRING` column | The document to read. |
| `questions` | Object | Field names and their questions. Use one field to ask one question. |

### Answer positions

Quail also returns the position of each answer in a second struct. Its
name is the alias followed by `_span`, and it has the same fields. Each
field holds the `start` and `end` character positions of its answer.
For the contract above, `lease_span` is
`{"end_date": {"start": 14, "end": 27}, "signer": {"start": 39, "end": 47}}`.
In Python, `text[start:end]` returns the answer.

Each question is a separate extraction. On the Quail backend, the
questions about one document read the same document KV.

### Filter on answers

Use the extraction's `AS` name to filter by an answer field in `WHERE`.
For example, with the same `contracts` table, keep leases whose
extracted end date contains "2027":

```sql
SELECT c.id,
       AI.EXTRACT(c.text, {'end_date': 'When does the lease end?'}) AS lease
FROM contracts c
WHERE lease.end_date LIKE '%2027%';
```

Quail extracts the answer once and uses it for both the filter and the
result. Documents with no answer are excluded. Use
`lease.end_date IS NULL` to keep documents where no end date was found.

Answer fields support the conditions listed in [WHERE and ON](/docs/user-guide/sql/sql-functions#where-and-on).
You can also test an answer's position. For example,
`lease_span.end_date.start < 500` keeps answers that start within the
document's first 500 characters.

Quail may reorder a table's AI filters, classifications, and extractions
to reduce estimated work. A condition on an answer runs after the
extraction that produces it. Use a [planning hint](#planning-hints) to
set the expected fraction of documents that pass, or pass
`order="as_written"` to `session.sql()` to preserve the written order.

### Limits

- Use a model that supports `AI.EXTRACT`. See
  [Supported models and GPUs](/docs/user-guide/models).
- Filters on answers run on the Quail backend only.
- `ORDER BY`, `DISTINCT`, and `GROUP BY` cannot use the result of an
  extraction.

For the Python form, see
[`ai_extract()`](/docs/user-guide/python-api/ai-functions#ai_extract).

## Planning hints

Use `HINT(condition, {'selectivity': fraction})` on a classification
label or extracted answer to estimate the fraction of documents that
pass. Quail uses the estimate to choose the order of AI functions.

For example, in the lease query above, replace the `WHERE` clause with:

```sql
WHERE HINT(lease.end_date LIKE '%2027%', {'selectivity': 0.4})
```

The hint estimates that 40% of documents pass. The default is 20%.
A hint affects planning only; it does not change which rows pass.
